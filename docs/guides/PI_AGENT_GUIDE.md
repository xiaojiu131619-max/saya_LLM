# Pi 智能体使用说明书

> 适用版本：拾壹 v0.5.0 ｜ Pi 内核 `@earendil-works/pi-coding-agent` 1.5.0
> 配套文档：`docs/AGENT_PROTOCOL.md`（协议契约，面向改代码的人）
> 本手册面向**用 Pi 干活的人**：怎么装、怎么配、怎么发任务、权限怎么判、出问题怎么办。

---

## 1. Pi 是什么

Pi 是拾壹里内置的**本地智能体内核**。它和「主对话」是两条完全不同的链路：

| | 主对话 | Pi 工作区 |
|---|---|---|
| 进程 | 应用内置的补全引擎 | 宿主拉起的 Node 子进程（`node cli.js --mode rpc`） |
| 工具 | 应用直接调 HTTP | 模型调宿主代理工具（文件 / 命令 / 画布） |
| 权限 | 无（只有本机服务鉴权） | 三档：只读 / 守门 / 放行 |
| 技能 | 无 | 宿主侧技能树路由后注入 |
| 长期记忆 | 无 | 跨会话共享（`save_memory`） |

一句话：**主对话是「和模型聊天」，Pi 是「让模型在你电脑上干活」。**

---

## 2. 一次任务的完整链路

```
你在 Chat 的 Pi 工作区输入一句话
   │
   ├─ ① 宿主技能雷达：拿这句话去技能树里匹配（零模型成本）
   │     命中 → 【本轮技能说明】正文（约 8000 字符预算，最多 2 个技能）
   │
   ├─ ② 宿主拼装 prompt：
   │     【长期记忆】+【本轮技能说明】+【用户任务】
   │
   ├─ ③ 写入 Pi 的 stdin（JSONL，命令 id = run-N）
   │
   ├─ ④ Pi 调模型 → 需要动手时回调宿主工具桥（127.0.0.1 + 随机 token）
   │     宿主按权限档判定：放行 / 拒绝 / 弹窗问你
   │
   ├─ ⑤ Pi 的 stdout 逐行吐事件 → 宿主打上 runId → Tauri 事件 → 前端
   │
   └─ ⑥ 收尾：产物解析 → 产物门校验 → 写回气泡（正文 / 步骤 / 指标 / 产物卡）
```

关键点：**模型永远碰不到你的文件系统**。模型只能请求宿主代劳，宿主是权限的唯一收口。

## 3. 开始之前

### 3.1 装 Pi 内核

拾壹 → **设置中心 → 核心更新 → Pi 智能体内核**：

- 显示「未安装」→ 点安装（走 npm 镜像源）；
- 已安装 → 可以查看版本、切换镜像源、回滚到上一个版本；
- 安装目录：`%APPDATA%\AgentLLM\pi\node_modules\@earendil-works\pi-coding-agent`。

### 3.2 准备一个模型引擎

Pi 自己不带模型，它需要一个 **OpenAI 兼容端点**。三种都行：

- 拾壹里加载 GGUF（走内置 llama-server）；
- 启动 NiNfer 引擎；
- 启动 Strata 引擎。

默认「**自动对接**」开着：拾壹会自动探测 NiNfer → Strata → llama-server，
把基址、模型 ID、Key 填好。探测不到就明确报错，不会瞎猜。

> 端点没起来时 Pi 也能启动，只是发消息会失败并提示「没有检测到正在运行的模型引擎」。

### 3.3 目录约定

| 目录 | 作用 | 默认位置 |
|---|---|---|
| Agent 配置目录 | `models.json` / `settings.json` / 扩展 | `%APPDATA%\AgentLLM\pi\agent` |
| 工作区根目录 | 每个 Pi 会话一个子目录 | `%APPDATA%\AgentLLM\pi\work` |
| 会话目录 | Pi 自己的 session 文件 | `%APPDATA%\AgentLLM\pi\sessions` |
| 技能库目录 | 技能树根目录 | `D:\Projects\Agent_LLM\app\resources\pi\skills` |

在 **Agent 页 → Pi → 高级设置** 里可以逐项改，填错时点「重新探测」自动回填。

## 4. 三个入口

### 4.1 Chat 的 Pi 工作区（主力）

点对话框左上角的头像，在**主对话 ↔ Pi 工作区**之间切换。Pi 工作区里：

- 左侧是**工作区选择器**：一个真实本地文件夹。只有这个文件夹里的文件和命令才受 Pi 权限控制；
- 每个工作区一套独立会话，互不干扰；
- 输入框左边那枚盾牌可以随时切权限档；
- 输入框右边「⋯」里能直接挂技能树和 MCP 服务；
- **不支持聊天附件**——文件请放进工作区，然后用文字描述任务。

### 4.2 Agent 页 → Pi 面板（设置与状态）

模型 · 引擎 · 智能体 → **Agent → Pi**。这里管四件事：

1. **运行状态**：PID、当前模型、当前会话、工作区路径、运行日志（stdout/stderr）；
2. **模型端点**：自动对接开关；关掉后手填「模型 ID / 引擎地址 / API Key」；
3. **随应用启动**：开 = 启动软件就拉起 Pi，关闭软件一并停；关 = 只在你点「启动」时拉起；
4. **高级设置**：Node 路径、Pi CLI 路径、四个目录、重新探测。

「使用本机服务密钥」按钮：本机服务开了鉴权时，Pi 必须用同一把 Key，否则 401。

### 4.3 Pi 浮窗（快聊）

标题栏右侧的机器人图标（最小化按钮左边）。独立小窗、置顶、不进任务栏。

- 可以粘贴截图（Ctrl+V）交给支持视觉的模型；
- **对话不写入主界面历史**，正式对话请用 Chat 的 Pi 工作区；
- 权限确认不在浮窗弹——主界面的全局运行时统一弹窗，浮窗只提示「请到主界面确认」；
- Chat 的任务没跑完时，浮窗不发送，避免两个窗口抢同一个 Pi 进程。

## 5. 权限档：Pi 能干什么

权限档决定宿主怎么对待模型的每一个动作。**只对工作区文件夹内的文件与命令生效。**

| 工具 | 只读（plan） | 守门（auto） | 放行（full） |
|---|---|---|---|
| `read_file` / `list_dir` | 放行 | 放行 | 放行 |
| `write_file`（新建） | **拒绝** | 放行 | 放行 |
| `write_file`（覆盖已有文件） | **拒绝** | **逐条询问** | 放行 |
| `edit_file` | **拒绝** | **逐条询问** | 放行 |
| `run_command` | **拒绝** | **逐条询问** | 放行（危险命令黑名单仍拦） |
| `run_python` | **拒绝** | **逐条询问** | 放行 |
| `save_memory` | **拒绝** | **逐条询问** | 放行 |
| `canvas_status` / `canvas_list_workflows` / `canvas_get_workflow` | 放行 | 放行 | 放行 |
| `canvas_run`（生图） | **拒绝** | **逐条询问** | 放行 |
| `canvas_cancel`（中断画布） | **拒绝** | **逐条询问** | 放行 |

补充：

- 权限弹窗**等待 120 秒**；超时按「拒绝」处理，并会在界面上说明「已超时自动拒绝」。
- 权限档**跟着工作区走**：切换工作区时自动切到该工作区记住的档位；
- 「放行」档仍有危险命令黑名单（`format`、`diskpart`、`bcdedit`、递归删除、注册表删除等）。

## 6. 技能树：模型怎么知道「该按哪套规矩做」

Pi 自己的 skill 机制被关掉了（`--no-builtin-tools`），技能由**宿主侧雷达**路由后注入上下文。

### 6.1 路由流程

1. 你发一句话 → 宿主拿这句话去技能库目录匹配（纯关键词，**不花模型钱**）；
2. 命中条件按优先级：`触发词` → `description` 关键词 → 别名 → 分类路径（`_tree.json` 两级路由）；
3. `not_for` 命中的技能直接排除（例如说「不要写报告」就不会注入写作技能）；
4. 转发器互斥：生图 / 生视频这类技能同时命中时只保留一个，避免正文打架；
5. 取前 2 个技能，正文合计不超过 8000 字符；
6. 拼进 prompt 的【本轮技能说明】。

### 6.2 技能库目录

默认 `D:\Projects\Agent_LLM\app\resources\pi\skills`（239 个技能）。
每个技能一个目录，根部有 `SKILL.md`：

```yaml
---
name: living-ascii-wallpaper
description: 把静态图片做成会动的 ASCII 动态壁纸
triggers:
  - 动态壁纸
  - ascii 壁纸
not_for:
  - 纯文字排版
tools:
  - read_file
  - write_file
---
```

在 **Agent 页 → 技能** 页可以改目录、看索引、**试跑**路由（输入一句话看命中了谁、注入多少字符）。

> 换机器或重装后，如果 localStorage 里存着旧的技能库路径，
> 显式配置优先级最高，会盖过新的候选链——在技能页「更改目录」重选一次即可。

## 7. 产物与画布

- 模型写文件 / 跑画布工作流后，产物落在**当前工作区**里；
- 产物卡出现在气泡下方，可直接预览图片 / PDF / 文本；
- **产物门**：任务要求文档却没检测到产物时，气泡会标红「产物校验未通过」——防止模型嘴上说做了、实际没做；
- 画布相关动作全部走 `canvas_*` 工具，受权限档控制。

## 8. 排障手册

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| 「没有检测到正在运行的模型引擎」 | 端点没起来 | 模型页加载 GGUF，或启动 NiNfer / Strata；或关掉「自动对接」手填地址 |
| 「401 / invalid api key」 | 本机服务开了鉴权，Pi 用的 Key 不一致 | Agent 页 → Pi → 「使用本机服务密钥」，然后停止并重启 Pi |
| 「Pi 连不上模型端点」 | 地址写错 / 引擎已停 | 用「重新检测」或手填 `http://127.0.0.1:<端口>/v1` |
| 气泡一直「Pi 执行中」 | Pi 还在跑（可能在等权限） | 看标题栏状态；点「停止生成」 |
| 「模型请求失败，正在重试 N/3」 | 端点报错 | Pi 自带 3 次重试；仍失败会在气泡里写明原因 |
| 「权限请求已超时，已自动拒绝」 | 弹窗挂太久（>120 秒） | 重新发起任务，在弹窗里尽快选择 |
| 「工具 xxx 已被宿主禁用」 | 模型想用非宿主工具 | 技能说明里要求的工具不存在时，让它改用 `run_python` / `run_command` |
| 「产物校验未通过」 | 模型说做了但没落文件 | 看步骤里有没有 ✓；没有就是没执行 |
| Pi 起不来、界面毫无反应 | 旧版前端 / 未重启 | 停止后重新启动应用 |

**日志在哪**：Agent 页 → Pi → 运行日志（stdout / stderr 全量，可清空）。
宿主侧每次 prompt 也会打一行 `[pi] prompt run-N: …`，便于对轮次。

## 9. 本轮修掉的运行期缺陷（2026-11-07）

第 1~5、7~8 条在真实界面里复现并验证过；第 6 条按事件时序证据验证（Pi 的 `agent_end` 必在下一轮 `response` 应答之前，按应答打标签即可对齐）。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | Pi 气泡的 `tok / TTFT / tok/s / 生成耗时` 永远是 `--` | `UPDATE_MESSAGE` reducer 没接 `stats` 字段，指标被丢弃 | reducer 补上 `stats` |
| 2 | 同上，只有「42 tok」出来了，TTFT / 耗时仍是 `--` | `genTime` 只算首末增量之差，单次增量时为 0 | `genTime` 改为「发 prompt → 最后一个增量」，与主对话同口径 |
| 3 | Pi 的所有运行期错误**用户完全看不到** | `PiRuntimeContext.error` 没有任何界面出口 | 加全局错误横幅（右上角，可关闭）；「未加载模型」这类常态不弹 |
| 4 | 权限等待超时后点「允许」报「权限回传失败」 | 后端超时静默拒绝，前端弹窗不关 | 后端超时回一条 `pi:permission_expired`，前端关弹窗并说明原因 |
| 5 | 「启动」按钮每点一次就新建一个 `settings-<时间戳>` 会话目录并重启 Pi | 会话 id 用时间戳 | 改用固定会话 `pi-auto`，目录稳定、重复点击不再重启 |
| 6 | 取消上一轮后马上再发，新一轮可能被上一轮的收尾事件提前结掉 | 后端用全局 `PI_RUN_ID`，`run()` 时就换，导致上一轮的迟到事件打到新一轮 | 改为**按 Pi 的 RPC 应答切换轮次标签**（Pi 认下这条 prompt 之后才算这一轮的） |
| 7 | 只读档下模型仍能打断画布队列 | `canvas_cancel` 漏了权限判定 | 补齐三档判定（只读拒绝 / 守门询问 / 放行直跑）+ 单测 |
| 8 | 工作区里名为 `x&calc.exe` 的文件，点「用系统打开」会凭空启动 calc.exe | 路径原样交给 `cmd /C start`，`&` 被当命令分隔符 | 整条命令行加引号（cmd 引号内不解释元字符）+ 单测 |

验证口径：`npx tsc -b` 零错误、`npm run lint` 零问题、`cargo test --lib` **273 通过 / 0 失败**（新增 3 条单测）；
并在真实 WebView2 里用本地 mock 端点跑通了「发任务 → 权限弹窗 → 放行 → 工具执行 → 产物/指标回写」全链路。

## 10. 已知限制（暂未改）

1. **工具桥是单线程串行的**：一次权限确认或长命令会把整个桥占住，
   这期间其它工具请求排队（`canvas_run` 已单独放线程，其余没有）。
   症状：第一个权限弹窗没点之前，第二个弹窗不会弹出来。
2. **Pi 是全局单实例**：Chat 的 Pi 工作区和 Pi 浮窗共用同一个子进程。
   Chat 的任务在跑时，浮窗会提示「Pi 正在被其他会话使用」；任务结束后 Pi 进程仍在，
   浮窗需要先让 Chat 切换会话才能接管。
3. **宿主没有轮次级超时**：模型端点返回异常流（连接建立但不结束）时，气泡会停在「Pi 执行中」，
   只能靠「停止生成」结束。
4. **Pi 工作区不支持聊天附件**：请把文件放进工作区再用文字描述任务。
