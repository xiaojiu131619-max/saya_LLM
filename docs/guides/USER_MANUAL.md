## 1. 拾壹是什么

拾壹是**本地大模型的一站式管理台**：把散落在硬盘里的 GGUF 模型、内核、引擎和创作工具收进一个界面，
并给它们配上一套能真正对话、能调用工具、能画图的工作台。

它由三棵独立的界面树组成（`app/src/features/workspace/WorkspaceShell.tsx`）：

| 界面树 | 进入方式 | 干什么 |
|---|---|---|
| **模型 · 引擎 · 智能体** | 启动后的默认页 | 加载模型、管引擎、管智能体 |
| **对话** | 左下角「切换到对话」 | 跟模型聊天，Pi 智能体干活 |
| **设置中心** | 左下角「软件设置」 | 外观、目录、统计、工具、维护 |

三条核心原则：

1. **本地优先**——模型权重、对话历史、统计全部在本机；除更新下载外不联网。
2. **模型不碰你的文件**——原生工具默认全关；Pi 工作区的每个动作都要过权限档。
3. **引擎可切换**——主模型（llama.cpp）、NiNfer、Strata 三条后端，显存上互斥，按需切换。

## 3. 五分钟上手

```
① 装内核    设置中心 → 核心更新 → llama.cpp 推理内核 → 更新
② 加目录    设置中心 → 软件设置 → 本地模型运行 → 选择目录（选存放 .gguf 的文件夹）
③ 刷列表    模型列表 → 刷新列表
④ 调参数    点模型卡片 → 加载参数 → 确认上下文长度与 GPU 卸载 → 加载模型
⑤ 聊天      加载成功自动跳到对话页，输入框回车即发
```

可选：

- **视觉模型**：卡片上带「视觉」标签的模型支持图片输入；
- **工具能力**：卡片带「工具」标签的模型支持 function calling（需在「工具」页开原生工具）；
- **智能体**：把任务交给 Pi 工作区，它能读写文件、跑命令、调画布。

## 4. 模型管理

入口：**模型 · 引擎 · 智能体 → 模型列表**。页面标题「模型管理」，副标题「扫描本地 GGUF 文件，选择模型并进入参数加载。」

### 4.1 工具条

| 控件 | 说明 |
|---|---|
| 搜索模型… | 实时过滤名称 / 家族 / 描述 / 标签 |
| 刷新列表 | 重扫磁盘（`scan_models`），解析 GGUF 头 |
| 默认排序 | 按名称 / 大小 / 更新时间 |
| 列数 | 1 列 / 2 列 |
| 魔搭下载 | 打开 modelscope.cn 下载 GGUF |

### 4.2 计数行

格式：`{N} 个模型 · {N} 个已加载 · 最近使用 {N} 个 · {状态提示}`。

状态提示有三种：

- 「已发现 N 个本地 GGUF 模型」；
- 「已发现 N 个本地 GGUF 模型（另有 M 个向量模型，见「向量服务」）」；
- 「模型目录里暂未发现 GGUF 文件。」

### 4.3 模型卡片

每张卡显示：名称、架构标签（稠密 / MoE）、参数量与体积、量化类型、能力标签（视觉 / 工具 / 视频候选）、
历史速度、主题色。点卡片进入**加载参数页**。

> **向量模型不在这里出现**。Embedding / Rerank 模型被单独收进「向量服务」，
> 因为 KV 量化、投机解码、工具模板对它们没有意义。

### 4.4 空态的 3 步引导

没扫到模型时，页面给出三步：

1. 进入设置 —— 点下方按钮进入「设置」页
2. 选择目录 —— 添加存放 .gguf 文件的本地文件夹
3. 开始加载 —— 刷新后选择模型并点击加载

## 5. 加载参数详解

入口：**模型列表 → 点模型卡片**。这是整个软件最需要理解的一页——每个参数都直接决定显存占用与生成速度。

页面分两个标签：**加载参数** / **模型信息**，下方有 **自动调参 · 重置 · 加载模型** 三个按钮和一条加载进度条。

### 5.1 头部信息

顶部信息卡 7 项（只读）：架构 / 层数 / 上下文 / 专家数 / 嵌入维度 / 注意力头 / K/V 长度。
右侧显示**预计显存**，分「权重 / 计算 / 运行 / 余量」四段，标注来源（实测校准 / 近似估算 / 张量估算），
并显示设备显存占用 `已用 / 总量 GB`；超容量时追加「· 预测超容量」。

「更换模型头像」按钮弹「头像与主题色」弹窗：内置品牌 logo 网格（不支持上传图片）+ 12 个预选色 + 取色器，
主题色会同步到模型卡片、对话头像与使用统计。

「API 名」输入框：给这个模型起一个调用名，失焦或回车保存。

### 5.2 区块一「推理与显存」

| 参数 | 控件 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| 上下文长度 | 滑块 + 数字框 | 512 ~ 模型上限，步长 512 | **32768** | 模型一次能记住的词元总数，决定长文档、长对话、代码分析的上限。调大后 KV 缓存线性增长、加载更慢，显存不足可能直接加载失败。日常 32K 通常够用 |
| —快速定位 | 可点标签 | 10K / 32K / 64K / 100K / 160K / 200K | — | 一键跳常用档，超出模型容量的自动隐藏 |
| GPU 卸载 | 滑块 + 数字框 | 0 ~ 层数+1 | **拉满（层数+1）** | 把模型前 N 层放到显卡。越高越快、显存越大。**内核把输出层也算一层**——用层数会留一层在 CPU，生成速度成倍下降 |
| 将 KV 缓存卸载到 GPU 内存 | 开关 | — | **开** | 对话历史的 KV 也放显存，生成时不必反复从内存搬运。省显存但长上下文明显变慢 |
| 快速注意力 | 开关 | — | **开** | Flash Attention，显著降低注意力计算的显存与耗时。出现花屏、答非所问、驱动兼容问题时可关 |

### 5.3 区块二「缓存与运行行为」

| 参数 | 控件 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| 物理批处理大小（ubatch） | 数字框 | 1 ~ 8192，步长 64 | **512** | 一次真正送进计算图的词元数，影响预填充显存峰值。调小省显存但提示词更慢，256–512 比较稳 |
| K 缓存量化类型 | 开关 + 下拉 | f32 / f16 / bf16 / q8_0 / q4_0 / q4_1 / iq4_nl / q5_0 / q5_1 | **关（f16）** | 压缩 K 缓存省显存。q8_0 基本无损最推荐；q5/q4 更省但可能影响长上下文质量 |
| V 缓存量化类型 | 开关 + 下拉 | 同上 | **关（f16）** | 压缩 V 缓存省显存。q8_0 通常安全，更激进会让长文质量下降 |
| 强制 MoE 权重留在 CPU 的层数 | 滑块（**仅 MoE**） | 0 ~ 层数 | **0** | 前 N 层专家留内存，显著降显存但计算更慢。0 = 全部按 GPU 卸载 |
| MoE 专家 GPU 缓存 | 开关 + 数字框（**仅 MoE**） | 0 关；开启默认 2048 MiB | **0（关）** | 给留在内存的专家在显存开缓存，1–4 GB 常能明显提速，但直接吃显存 |
| 稠密 FFN 留在 CPU 的层数 | 滑块（**仅稠密模型**） | 0 ~ 层数 | **0** | 前 N 层 FFN 留内存，越大越省显存越慢 |
| 空闲时自动卸载 | 开关 + 分钟框 | 1 ~ 1440 分钟 | **关 / 15 分钟** | 一段时间无输入无输出就自动停止模型、释放显存。有新消息会重新计时 |
| 记住该模型的加载设置 | 开关 | — | **开** | 保存本模型参数供下次沿用；关则每次回默认 |

### 5.4 区块三「高级参数」（可折叠）

副标题「线程、批处理、RoPE、聊天模板等」。

**左列**

| 参数 | 默认 | 说明 |
|---|---|---|
| CPU 线程池大小 | **-1（自动）** | 生成阶段线程数。手动通常取物理核心数，设太高会抢 CPU 反而变慢 |
| 最大并发预测数（parallel） | **-1（自动）** | 同时服务的请求槽位数。单人保持自动或 1；多人/接口并发时调大，每槽都占 KV 与解码资源，显存明显增加 |
| 统一 KV 缓存 | **开** | 所有槽共享一块 KV 池，长请求可借用空闲槽容量。关则每槽固定分配，隔离性好但更易浪费 |
| 保持模型在内存中 | **关** | mlock 锁在物理内存避免换出。内存紧张时开启会拖慢全系统 |
| 跳过启动预热 | **关** | 加载更快，但第一条真实请求承担初始化开销，可能明显更慢 |
| 尝试 mmap() | **开** | 内存映射读模型，通常更快更省内存。机械盘/网络盘卡顿时可关 |
| 大张量按需读取 | **内核默认** | 超大张量按需读盘。内核默认只对 >4 GB 张量启用，需要 mmap |
| SWA 完整缓存 | **关** | 滑动窗口注意力按完整上下文分配 KV，长文更稳但显存明显增加 |
| 每路上下文上限 | **关（内核默认）** | 仅「统一 KV 缓存」开启时显示。限制单槽上下文，防长请求占满共享池 |
| 提示词缓存上限 | **关（内核默认）** | 单位 MiB。缓存重复前缀加快多轮；0 关闭，-1 不限，默认 8192。开太大挤占其他程序内存 |

**右列**

| 参数 | 默认 | 说明 |
|---|---|---|
| 评估批处理大小 | **512** | 逻辑批处理上限。调大加快长提示词预填充但增计算显存，一般 512–2048 且不超上下文长度 |
| RoPE 频率基 | **关（自动）** | 覆盖旋转位置编码基频。乱改会让输出退化 |
| RoPE 频率比例 | **关（自动）** | 按 1/N 扩展上下文。无明确依据保持自动 |
| 专家数量 | 只读 | 从 GGUF 读出的 MoE 专家数，仅用于估算，不是启动参数 |
| 推测解码 | **关闭** | 关闭 / 内置多词元预测（MTP）/ DSpark 草稿侧车 / DFlash 草稿侧车（按模型能力置灰）。草稿先猜多 token 再由主模型验证，命中更快；不匹配或显存不足会变慢甚至启动失败 |
| 草稿深度 | **关（内核默认）** | 仅推测解码≠关闭时显示。1~16，每步草稿 token 数 |
| 草稿上下文批大小 | **0** | 仅推测解码≠关闭时显示。0 = 跟随主模型 |
| NextN / MTP 元数据 | 只读 | 显示「当前不可用」= GGUF 声明了 MTP 层但当前内核缺架构图或可执行张量 |
| 多模态投影 GPU 卸载 | **开** | 仅带多模态投影的模型显示。关则投影留内存，多模态输入明显变慢 |
| 聊天模板 | **空** | 覆盖 GGUF 内置 Jinja 模板。填错会导致角色错乱或工具调用失效 |
| 种子 | **关（随机）** | 固定随机种子便于复现 |

### 5.5 「模型信息」标签

- **运行记录**：类型标签「启动」/「跑分」/「调参」；采样质量标签「稳定采样」/「未核实」/「有效参数变化」/「采样异常」/「旧记录·总量可用」；可展开调参日志；
- **模型介绍**：发布日期 / 许可协议 / 参数量 / 上下文；
- **GGUF 表头摘要**：真实读到的 metadata 字段；
- **基准测试**、**标签**。

### 5.6 自动调参

「自动调参」会固定当前 ctx，先找显存边界，再比较推测解码、MoE 缓存、FFN 卸载、KV、批处理与线程；
**整卡显存预算 90%**（见设备详情页）。跑完自动应用最优参数。

> 自动调参会反复启停引擎试参数，比较耗时且占用大量显存。

### 5.7 加载流程

点「加载模型」后依次：

1. 若有调参任务在跑 → 拒绝加载；
2. **先停掉旧实例**，等 1200 ms，再采 3 次显存基线；
3. 注册 ready / error / progress 监听，启动 `llama-server.exe`；
4. 收到 ready → 再采一次显存，解析日志里的 buffer，落运行记录；
5. 「记住该模型的加载设置」开着时保存参数；
6. 标记最近使用、激活模型 → **自动跳到对话页**。

加载过程有进度条（「日志阶段 {N}%」，旁注「由日志阶段映射，不代表文件读取比例」），可「停止加载」中断。

## 6. 对话

入口：左下角「切换到对话」。

### 6.1 两种对话

侧边栏左上角的**头像按钮**就是切换开关（悬停提示会写「切换到 Pi 工作区（当前：…）」）。

| | 主对话 | Pi 工作区 |
|---|---|---|
| 副标题 | 「本地模型 · 普通对话」 | 「Pi 内核 · 连续执行 · 沙箱内操控文件」 |
| 发送路由 | 补全流 | Agent 任务流 |
| 引擎 | 自动选：主模型 → NiNfer → Strata | Pi 自己的端点（也自动对接） |
| 产物卡 | 无 | 有 |
| 权限档 | 无 | 只读 / 守门 / 放行 |
| 技能树 | 不适用 | 有 |
| 上下文操作 | 「清除上下文」（全清） | 「压缩上下文（Pi 原生压缩）」 |
| 编辑重发 / 重新生成 | 允许 | 禁止 |
| 附件 | 支持 | **不支持** |

Pi 工作区内部再按**工作区**（真实本地文件夹）二次隔离：每个工作区一套独立会话。

### 6.2 会话侧栏

| 控件 | 说明 |
|---|---|
| 展开/折叠侧边栏 | 圆形按钮；窄窗口锁定折叠 |
| 拖动分隔条 | 调宽度（默认 288px），双击恢复默认 |
| 头像按钮 | 切换 主对话 ⇄ Pi 工作区 |
| 新建对话 | 建新会话 |
| 切换 Agent 工作区 | 仅 Pi 工作区：下拉选文件夹 / 「选择本地文件夹…」 / 「技能树」 |
| 搜索对话与内容 | 标题模糊 + 正文检索，命中处显示摘要 |
| 多选删除 | 进入多选 → 「删除 N 个」 |
| 分组 | 按天分组：今天 / 昨天 / M月D日 |
| 会话行 | 点击切换；多选模式下改为勾选 |
| 导出会话 | 悬浮按钮 |
| 删除会话 | 悬浮按钮，**无二次确认** |
| 右键菜单 | 用模型重新生成标题 / 导出会话 / 删除会话 |
| 状态卡 | ctx / 显存 / 内存 / GPU 四格读数 |

### 6.3 消息气泡

**用户气泡**：复制 / 编辑 / 重发 / 删除。编辑时 Ctrl/⌘+Enter 提交、Esc 取消。

**模型气泡**（从上到下）：

1. **思考过程** —— 可折叠；
2. **工具调用面板** —— 「正在调用工具（3/5 完成）」或「调用了 N 次工具」；
3. **Pi 执行步骤** —— 「Pi 执行中」/「执行了 N 步」/「等待权限确认」/「等待 Pi」；
4. **产物卡** —— 图片 / PDF / 文本预览；
5. **正文** —— Markdown；
6. **警告条** —— 交付护栏与产物门结论；
7. **统计行** —— ctx / tok / TTFT / tok/s / 生成耗时。

底部按钮：复制 / 重新生成 / 导出（`.md`）/ 删除。「翻译」按钮是占位，永久禁用。

### 6.4 输入区

| 控件 | 说明 |
|---|---|
| 上传文件 | 支持粘贴图片和跨应用拖入 |
| Pi 权限档 | 仅 Pi 工作区：盾牌图标点开三档 |
| 思考强度 | 关闭 / 自动 / 思考 / 深思；下方显示实际下发挡位 |
| 技能与 MCP | 扳手图标：技能计数、技能树入口、MCP 服务器连接开关 |

> **发送快捷键**由「软件设置 → 对话与输入」决定：
> 「Enter 发送」= Enter 发送、Shift+Enter 换行；「Ctrl+Enter 发送」= Enter 换行、Ctrl/⌘+Enter 发送。

### 6.5 右侧工作区面板

五个标签：**文件 / 终端 / 浏览器 / 画布 / 参数**。窗口不够宽时改成遮罩抽屉。

### 6.6 导出

侧栏「导出会话」→ 格式选 **Markdown / 纯文本 / JSON**；三个开关：思考过程（默认关）、统计数据（默认开）、工具调用（默认开）。
摘要行显示「N 条消息 / N 轮提问 / N 输出 token / N 个附件（不导出）」。

### 6.7 性能指标

| 显示 | 含义 | 显示 `--` 的情况 |
|---|---|---|
| `ctx N%（≈x / y）` | 本地会话累计上下文水位（估算）：中文按 1 token，其余按 4 字符 1 token，逐条累加正文 + 思考 | 会话还没有内容 |
| `N tok` | 本轮输出 token 数 | 引擎没上报 usage |
| `X.XXs TTFT` | 首 token 延迟 | 本轮无完整统计 |
| `X tok/s` | 解码速度 | 同上 |
| `生成耗时 XmXXs` | 本轮总生成耗时 | 同上 |

引擎侧速度样本不足时直接给 0 不展示：输出 <16 token 或解码阶段 <100ms。

### 6.8 交付护栏

主对话拿不到正文时会给提示（**只提示、不重发**）：

- 「只调用了工具 X、没有给出正文」（同一工具连调 ≥3 次）；
- 「思考占满了输出预算，正文一个字都没出」；
- 「产物没写完（代码围栏或 <svg> 缺结束标记）」；
- 「输出达到上限被截断」。

## 15. 数据管理与危险操作

入口：**设置中心 → 数据管理**。副标题「管理模型/引擎/日志/归档目录，以及清除或重置本软件保存的本地数据。危险操作都会先二次确认。」

### 15.1 目录设置

| 目录 | 说明 | 默认 |
|---|---|---|
| 模型目录 | 扫描 GGUF 模型的位置，可添加多个；**移除只影响扫描，不删除磁盘上的文件** | 用户自选 |
| 引擎目录 | llama.cpp 版本化内核的安装位置。改动后新装的内核生效，**已装内核不会自动搬迁** | `<资源目录>\kernels` |
| 日志目录 | llama-server / NiNfer / Strata 的日志根目录 | `%APPDATA%\AgentLLM` |
| 归档聊天记录文件夹 | 导出/归档对话的写入位置，每个会话写成一份 JSON（含 Markdown 正文） | `%APPDATA%\AgentLLM\archives` |
| 自编译内核 | 指定自己编译的 llama-server.exe；留空则用随包内核 | 空 |

每个目录行都有「打开 / 修改 / 恢复默认」和「自定义 / 默认」徽章。

目录区底部按钮：**归档全部对话（N）** / 刷新 / 打开应用数据目录。

### 15.2 数据清除

| 行 | 按钮 | 效果 |
|---|---|---|
| 对话历史 | 清空历史 | 先中止在途生成，再清空全部会话/消息；**模型与目录配置不变** |
| 使用统计 | 清零统计 | 清零 token/耗时/速度（含 NiNfer / Strata） |
| 模型扫描缓存 | 清除缓存 | 只清解析结果，**模型文件不删** |
| 界面偏好 | 恢复默认 | 主题、强调色同步、毛玻璃、动画、发送快捷键、排序、列数、侧边栏宽度回出厂值 |
| 应用配置 | 重置配置 | **停止本地 llama-server**，config.json 回默认；需输入「重置配置」 |
| 出厂重置 | 出厂重置 | **停服务 + 清 config.json + 清缓存 + 撤销对外 API Key + 清前端 localStorage**；需输入「我确认清除」 |

### 15.3 全局危险操作清单

| # | 操作 | 破坏范围 | 二次确认 |
|---|---|---|---|
| 1 | **出厂重置** | 停服务、删配置与缓存、撤销对外 API Key、清对话/统计/界面偏好。**不可恢复** | 有，需键入「我确认清除」 |
| 2 | **重置应用配置** | 停服务，config.json 回默认 | 有，需键入「重置配置」 |
| 3 | **清空全部对话历史** | 删全部会话与消息 | 有 |
| 4 | **删除会话 / 多选批量删除** | 立即删，**不可撤销**，并中止该会话在途生成 | **无** |
| 5 | **清除上下文** | 清空当前会话消息 + 输入框 + 附件 | **无** |
| 6 | **卸载模型** | 停 llama-server，模型置 standby | **无** |
| 7 | **删除 MCP 服务器** | 删配置条目，正在运行的连接一并断开 | 有 |
| 8 | **开启原生工具（执行命令/写入/编辑/补丁）** | 让模型以本机权限执行 shell、改写文件 | 默认全关，风险标「高」 |
| 9 | **添加 MCP 服务器** | 新增一个以用户权限运行的本机程序 | 页面常驻警告 |
| 10 | **释放对外 API + 允许局域网** | 监听 0.0.0.0，局域网可访问；Key 是本地明文鉴权 | 有 |
| 11 | **停止引擎** | 中断对话 + 释放显存；Strata 重启需十几分钟 | 有 |
| 12 | **空闲时自动卸载** | 到点自动停模型释放显存 | 有 |
| 13 | **核心更新「取消全部」** | 全局取消所有在跑的下载 | 有 |

> 本软件**没有「删除模型文件」的操作**。模型只被读取；「移除目录」不删磁盘文件。

出厂重置确认框原文：「一次性清除前述所有本地数据并刷新窗口。**模型文件、llama.cpp 内核与日志文件不会被删除。**」
此操作不可恢复。强烈建议在排错无果时再使用。

## 16. 排障手册

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| 「尚未发现真实 GGUF 模型」但硬盘明明有 | 模型目录没配，或没刷新 | 设置 → 软件设置 → 选择目录；回模型列表点「刷新列表」 |
| 「未检测到 llama.cpp 内核，请先下载核心后再加载模型」 | 内核没装 | 设置中心 → 核心更新 → llama.cpp 推理内核 → 更新 |
| 模型列表一直是 0，点「刷新列表」后正常 | 首屏只读缓存，缓存为空 | 点一次「刷新列表」即可 |
| 「检查更新失败：无法连接更新服务器」 | 代理不可用 | 设置 → 软件设置 → 网络代理，确认代理可用 |
| 「没有检测到正在运行的模型引擎」 | 端点没起来 | 模型页加载模型，或启动 NiNfer / Strata |
| 「401 / invalid api key」 | 本机服务开了鉴权，Pi 用的 Key 不一致 | Agent → Pi → 「使用本机服务密钥」，然后停止并重启 Pi |
| 「Pi 连不上模型端点」 | 地址写错 / 引擎已停 | 「重新检测」或手填 `http://127.0.0.1:<端口>/v1` |
| 气泡一直「Pi 执行中」 | Pi 还在跑（可能在等权限） | 看标题栏状态；点「停止生成」 |
| 「模型请求失败，正在重试 N/3」 | 端点报错 | Pi 自带 3 次重试；仍失败会在气泡里写明原因 |
| 「权限请求已超时，已自动拒绝」 | 弹窗挂太久（>120 秒） | 重新发起任务，在弹窗里尽快选择 |
| 「工具 xxx 已被宿主禁用」 | 模型想用非宿主工具 | 让它改用 `run_python` / `run_command` |
| 「产物校验未通过」 | 模型说做了但没落文件 | 看步骤里有没有 ✓ |
| 改了原生工具开关但没效果 | 需重新加载模型才同步 | 重载模型 |
| 改了 API Key 但外部客户端仍 401 | 新 Key 需重载模型 | 重新加载模型 |
| 对话报「请新开对话」 | 估算上下文超引擎 KV 池 90% | 新建会话 |
| 对话指标全是 `--` | 该轮无完整测速数据（中止/异常） | 正常，下一轮会有 |
| 外部客户端连不上 | 防火墙没放行端口 | 放行端口 + 重载模型 |
| 画布打开但提交任务失败 | ComfyUI 未连接 | 启动 ComfyUI 后重启画布网关 |

**日志在哪**：

- 推理内核 → 侧栏「llama 日志」；
- Pi → Agent → Pi → 运行日志；
- NiNfer → NiNfer 页 → 运行日志；
- Strata → Strata 页 → 运行日志；
- 画布网关 → Agent → 画布 → 网关日志；
- 应用日志 → 数据管理 → 打开应用数据目录。
