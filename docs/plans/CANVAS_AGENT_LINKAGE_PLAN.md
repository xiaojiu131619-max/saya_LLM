# 无限画布 × Pi Agent 联动计划（0.5 后）

> 状态：**M1 只读 / M2 生图 / M3 核心（图生图）已实施（2026-11-04）**，
> 见 `services/canvas_agent.rs` 与 `docs/plans/POST_0.5_BACKLOG.md`；
> 未实施：画布 UI「选中项交给Pi」按钮（画布前端无稳定全局 API，注入方案
> 会随画布升级碎掉——用「工作区已有图 → canvas_run 图生图」覆盖同一场景）。
> 本轮 0.5 只做Pi的管道、宿主工具代理、权限、会话和技能路由；画布联动放在后续清单。

## 1. 目标

让「无限画布」（本地 ComfyUI 工作台）和「Pi」（Agent）互相调用，而不是两个孤立的标签页：

- Pi能把「生图 / 视频 / 放大 / 换风格」交给画布执行，并把产物带回 Agent 会话；
- 画布能把当前选中的图片、节点、工作流交给Pi，让Pi继续修改、生成或解释；
- 两边共享同一份「会话工作区」和产物记录，但画布仍然是独立窗口/独立模块。

## 2. 用户场景

### 场景 A：Agent 生图

用户对Pi说：

> 画一张雨夜赛博朋克城市，16:9，存到工作区。

Pi应该：

1. 选 `image-gen` / `comfyui-workflows` 技能；
2. 把自然语言翻成画布能吃的 `prompt / negative / aspect-ratio / workflow`；
3. 调用画布执行；
4. 等待任务完成；
5. 把生成的 PNG 作为 Agent 产物卡返回，并写入当前会话工作区。

### 场景 B：画布选中 → 交给Pi

用户在画布选中一张图或一个节点，点击「交给Pi」：

- Pi收到：当前工作流 ID、选中图片路径、节点参数、用户附言；
- Pi可以：放大、换风格、反推提示词、继续生成、解释工作流。

### 场景 C：Agent 产物回到画布

Pi生成的图片/视频可以被画布当作输入图或参考图，继续编辑。

### 场景 D：Agent 解释画布

用户问：

> 这个工作流为什么出图这么慢？

Pi读取画布当前工作流 JSON 和运行日志，给出解释和优化建议（只读，不改画布）。

## 3. 架构

```text
┌──────────────┐      Tauri 事件 / 命令      ┌──────────────┐
│  画布窗口     │ ◄─────────────────────────► │  Rust 宿主    │
│  ComfyUI UI  │    canvas:* / agent:*       │  canvas_*     │
└──────┬───────┘                             │  pi_*         │
       │ HTTP                                 └──────┬───────┘
       ▼                                            │ 工具桥
┌──────────────┐                                    ▼
│ ComfyUI      │ ◄──── canvas_run 工具 ────── ┌──────────────┐
│ gateway 8190 │                              │ Pi           │
└──────────────┘                              └──────────────┘
```

### 3.1 宿主侧

- 新增 `services/canvas_agent_bridge.rs`（暂定）：
  - 读取画布状态、已安装工作流、当前选中项；
  - 提交任务到画布网关；
  - 轮询/订阅任务状态；
  - 把产物路径转成 Agent 会话工作区内的相对路径。
- 新增 Pi 工具（通过 `pi_tools` 代理）：
  - `canvas_status`：只读，返回画布/ComfyUI/Node 是否就绪；
  - `canvas_list_workflows`：只读，列出已安装工作流；
  - `canvas_run`：提交任务（受权限档约束）；
  - `canvas_cancel`：取消任务；
  - `canvas_attach`：把画布产物挂到当前 Agent 会话。
- 权限：
  - `canvas_status/list_workflows` 只读，三档都允许；
  - `canvas_run` 在守门档询问，放行档允许但校验工作流白名单与输出路径；
  - 输出目录固定到当前会话工作区的 `canvas/` 子目录，禁止任意绝对路径；
  - GPU 互斥：画布任务运行时不启动/不抢占 llama-server；与现有 `backend_gate` 协调。

### 3.2 画布侧

- 画布窗口增加「交给Pi」按钮：
  - 通过 Tauri 事件把选中图片/节点/工作流发送到 Agent 会话；
  - 不直接调用 Pi HTTP，统一走宿主。
- 画布保持独立窗口；不把画布前端合进主工程。

### 3.3 Pi侧

- 技能：
  - `image-gen` / `video-gen` / `media-enhance` / `comfyui-workflows` 的转发器改为调用 `canvas_run`；
  - 技能正文只负责「把用户话翻成画布参数」，不直接调 ComfyUI。
- 会话：
  - 每个 Agent 会话工作区下新增 `canvas/` 目录；
  - 画布产物作为 Agent 产物卡显示，来源标记「画布」。

## 4. 数据契约（草案）

### `canvas_run` 参数

```json
{
  "workflow": "image-krea2-aesthetics",
  "prompt": "雨夜赛博朋克城市，霓虹，电影感",
  "negative": "低清晰度，文字",
  "aspect_ratio": "16:9",
  "input_image": "canvas/input.png",
  "output_name": "rainy-city"
}
```

### 返回

```json
{
  "job_id": "canvas-job-...",
  "state": "queued",
  "artifacts": []
}
```

任务完成后通过事件/轮询返回：

```json
{
  "job_id": "canvas-job-...",
  "state": "done",
  "artifacts": [
    { "path": "canvas/rainy-city.png", "kind": "image", "title": "雨夜城市" }
  ]
}
```

## 5. 里程碑

### M1：只读联动

- Pi能读画布状态、工作流列表、当前选中项；
- 画布能「交给Pi」发送选中项；
- 不做生成。

验收：Agent 能回答「画布现在能出图吗」「这个工作流叫什么」。

### M2：Agent 提交生图

- `canvas_run` 走白名单工作流；
- 输出固定到会话 `canvas/`；
- 产物卡显示；
- 支持取消与超时。

验收：真实生成一张 PNG，产物卡可打开，取消能停。

### M3：画布 → Agent 继续编辑

- 画布选中图 → Pi放大/换风格/反推；
- 产物回写画布输入。

验收：选中图 → Pi放大 → 画布能继续用新图。

### M4：工作流解释与优化建议

- 只读工作流 JSON + 日志；
- 不自动改画布配置。

验收：Pi能指出耗时节点和参数问题。

## 6. 安全边界

- 工作流 ID 必须来自已安装画布包，不允许模型提交任意 JSON；
- 输出路径固定在当前会话工作区；
- `canvas_run` 受权限三档约束；
- 画布任务与 llama-server 的 GPU 互斥由宿主协调；
- 画布产物读取复用 `pi_tools` 的沙箱校验；
- 不在画布窗口里执行模型生成的任意 JS。

## 7. 风险

- **GPU 争用**：ComfyUI 和 llama-server 同时吃显存；需要显式互斥/排队。
- **长任务**：视频生成可能几分钟；需要进度事件、取消、超时。
- **ComfyUI API 漂移**：工作流 JSON 和节点参数随画布包版本变化；白名单要跟包版本走。
- **Windows 路径**：ComfyUI 输出路径、中文文件名、空格路径。
- **模型能力**：4B 模型把用户话翻成工作流参数可能不稳定；技能正文要给出明确字段和示例。

## 8. 非目标

- 不把画布前端合进主工程；
- 不让Pi直接编辑 ComfyUI 的任意工作流 JSON；
- 不在本轮实现画布任务队列 UI（先复用画布自己的队列）。
