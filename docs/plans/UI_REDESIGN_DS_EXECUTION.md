## 1. 执行目标与依据

对现有软件进行整体界面重排，使模型、对话、服务和设置具有统一的视觉层级、间距与操作位置。用户已选择“均衡密度：清晰留白，保留常用信息”和“各页面整体统一”。保持 Windows Fluent 风格，直接呈现可操作的工作界面。

详细设计规范见同目录 [UI_LAYOUT_REDESIGN_PLAN.md](UI_LAYOUT_REDESIGN_PLAN.md)。该文件第 3–6 节是布局、页面和视觉规范；本文件补充执行顺序、接入约束与验收方式。两份文件共同构成执行依据。实施时先读项目当前代码，文件映射以实际结构为准。

本次用户最终要求交付计划书，由 DS 执行。此前的“先做网页原型”已取消，不将制作独立原型列为实施前置任务。建议 DS 直接按阶段改造现有界面，并逐阶段提供实际截图供评审。

## 2. 必须遵守的边界

- 遵守根目录 `AGENTS.md`，新增界面与文档使用中文，必要技术名保留。
- 保留现有功能、真实数据与错误反馈，不用模拟服务或假进度替换实际功能。
- 不更改 `ctx`、`ngl`、KV cache、batch、parallel、max token、reasoning 等默认值、值域、自动挡含义、参数省略规则和请求构造。
- 加载、重置、自动调参、停止和后端选择继续由用户显式触发。页面切换或响应式布局变化不得触发上述操作。
- 不修改 Rust 服务生命周期、推理实现、统计口径和配置格式；若布局遇到业务问题，单独记录原因，不顺手扩大重构范围。
- 保留当前所有未提交修改；不得执行 `git reset --hard`、批量还原、批量格式化或清理用户文件。
- 不删除 `app/src-tauri/target/release/` 及其中的最新 `agent-llm.exe`；不得为解决构建问题清空整个 `target/`。
- 不升级依赖或引入新的 UI 框架。使用现有 React、Tailwind、`lucide-react`、模型家族图标及公共组件。
- 本轮不新增字体下载、不重做品牌、不做营销首页，不改变窗口初始尺寸和最小尺寸。

## 3. 统一布局规格

```text
标题栏：40px，保留品牌、拖动区域及窗口控制
┌────────┬──────────────┬────────────────────────────┐
│ 全局栏 │ 按需辅助栏   │ 页面标题 + 右侧操作         │
│        │              ├────────────────────────────┤
│ 对话   │ 对话：会话   │ 搜索 / 排序 / 页签          │
│ 模型   │ 设置：目录   ├────────────────────────────┤
│ 智能体 │              │ 主内容，独立滚动            │
│ 向量   │ 其他页无此栏 │                            │
│ 引擎   │              ├────────────────────────────┤
│ 服务   │              │ 对话输入 / 参数执行区       │
│ 日志   │              │ 按需出现，自然占位          │
│ 主题   │              │                            │
│ 设置   │              │                            │
└────────┴──────────────┴────────────────────────────┘
全局状态栏：28px，服务摘要 + 内存 / 显存 + 监控入口
```

| 项目 | 执行值 |
|---|---|
| 全局栏 | 常规 72px；800–959px 使用 56px 图标栏，提供中文提示 |
| 辅助栏 | 对话 224px；设置 192px；窄窗口使用可关闭抽屉 |
| 页头 | 最小 64px，标题 20px；长文本允许换行和增高 |
| 内容边距 | 常规 24px，窄窗口 16px；分组间距 24px |
| 内容宽度 | 列表/控制台最大 1440px；表单最大 960px；对话 800px，超宽可 896px |
| 字号 | 辅助 12px、正文 14px、对话 15px、分组 16px、标题 20px、指标 22px |
| 字距 | 统一 0，不按视口宽度缩放字号 |
| 圆角 | 控件 4–6px；重复模型项、弹窗、菜单最多 8px |
| 控件 | 常规高 36px；紧凑工具 32px；图标工具配中文名称与提示 |
| 色彩 | 中性背景 + 现有系统强调色 + 语义状态色；遵循详细方案第 5 节 |
| 分区 | 用标题、间距、分隔线组织；普通章节不套浮动卡片，不嵌套卡片 |
| 滚动 | 主内容 `min-height: 0`；长代码/日志内部滚动；无意外整页横向滚动 |

表单列数优先按可用内容宽度决定。不可为了塞下双栏而缩小字体或控件。模型品牌图标保留，删除无业务意义的点阵、光晕和持续动画。保留减少动态效果、主题自定义和毛玻璃能力。

## 4. 导航与组件接入

当前 `WorkspaceShell.tsx` 依据 `currentView` 切换模型、对话和设置三个工作区；服务类页面嵌在 `ModelWorkspace.tsx` 内。全局栏接入时应重新分配导航职责，避免新旧侧栏同时占位。继续使用当前 `ViewType` 和 `SET_VIEW`，无需引入新路由库。

| 全局入口 | 当前视图标识 | 选中规则 |
|---|---|---|
| 对话 | `chat` | 对话页面 |
| 模型 | `home` | `home` 与 `modelLoad` 都选中模型 |
| 智能体 | `agent` | 智能体页面 |
| 向量 | `embedding` | 向量服务页面 |
| 引擎 | `fast27b` | fast-27b 页面 |
| 服务 | `apiStatus` | API 服务页面 |
| 日志 | `llamaLogs` | 当前主服务日志页面；其他日志入口继续按原路径保留 |
| 设置 | `settings` | `settings`、`kernel`、`usage`、`tools`、`modelTheme`、`data` 均选中设置 |

建议公共组件仅承担以下职责，若已有组件满足要求则直接复用：

- `WorkspaceNavigation.tsx`：入口、选中状态、主题/设置工具、响应式宽度。
- `PageLayout.tsx`：页头、工具栏、主内容与底部操作的布局槽位，不拥有业务数据。
- `PageHeader.tsx`：标题与操作的共同对齐线，处理长标题、操作换行。
- `SystemStatusStrip.tsx`：复用当前数据源，单实例展示摘要及监控入口。

不能在新壳层和旧页面分别挂载两套状态监控，不能同时渲染隐藏版与展示版业务页面。保留懒加载；不为视觉统一一次性预加载全部页面。会话草稿、列表偏好及服务状态沿用已有存储方式，不新增第二套状态来源。若改变页面挂载方式，检查流式输出、订阅清理、草稿和滚动恢复是否退化。
