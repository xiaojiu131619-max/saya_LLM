# 自动调参优化与验证记录

## 范围

本轮仅优化自动调参及其配置构造、任务生命周期和回归测试。显存预测、实测校准与 GGUF 解析算法未修改；不改用户保存的默认加载或推理参数。

## 已实现

- 测量与正常加载共用完整配置构造器，保留 ubatch、线程、parallel、独立 K/V 开关、RoPE、模板和侧车。测量服务显式使用本地监听、无 API key、禁用自动 CPU 回退；正式 API 配置不受影响。
- 首点显存不足后继续降档；区分 OOM、不支持参数、致命错误和取消。不支持量化 KV 时回到可执行的 KV 配置继续卸载搜索，避免把不受支持的类型带到所有降档点。
- MoE 的 ncmoe 按重复层数（block_count）搜索，不按每层专家数量。候选去重，粗测上限 32 点，保留 ngl=0 降档路径，并细化已观测到的 GPU/CPU 专家层数边界。上下文按几何步长上探至模型 max_ctx。
- 流式响应中第一个非空生成内容用于 TTFT。每点分离冷提示、预热和热测；粗测 2 次热样本，靠前三个候选分别重启并测 5 次热样本，再按复测结果排序。失败复测不能回用其粗测结果作为最佳值。
- 使用 run_id/model_id 隔离任务和事件；停止请求后保持 stopping，等待启动线程及测量服务回收才发布终态。普通停止和内核更新不得抢占调参任务，调参也不会自动停止用户已有模型。
- 页面卸载不丢任务监听；恢复状态时缓冲终态，防止旧 running 快照造成永久忙碌。取消后主动查询后端状态对账。
- 自动应用在 reducer 中原子核对任务身份、模型签名（含侧车）及完整加载配置。配置已变化则保留用户现值，不自动覆盖；恢复的旧任务不产生自动应用授权。
- 成功、失败与取消均保留结构化实验资料，复用模型运行记录；IPC 不发送真实 API key，实验数据脱敏。旧记录保持可读取。
- 新增统一 npm test 入口及 CI 前端回归步骤。

## 结果解释与边界

没有启动真实模型或 GPU 推理，未据此宣称任何吞吐提升。真实内核流式响应、设备遥测和完整调参流程仍需实机验证。

搜索是有预算的候选搜索，不承诺配置空间的全局最优。短提示显存采样不代表满上下文峰值，热缓存吞吐也不代表长对话或交互体验。GPU 候选缺少有效显存遥测时终止而不声称符合 90% 预算；CPU 无遥测时显示未知，不显示为已验证的 0%。
